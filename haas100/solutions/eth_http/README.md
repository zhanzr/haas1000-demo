# eth_http — HaaS100 Ethernet + embedded web server

The board gets an IP over the **CH395Q Ethernet** (stock `eth_lwip_tcpip_init`
at boot + netmgr) and serves the e_server single-page app (see
`../../../../e_server/`) on **port 80** using lwIP BSD sockets.

The page/API is the HaaS100 adaptation of `e_server`:
- **LED tab** — controls the 5 on-board LEDs (GPIO 40/41/36/35/34) via `led_switch()`.
- **ADC tab** — plots the **first 3** GPADC channels: `chan0`, `battery`, `chan2` (mV).
- **Board info tab** — arch (`cortex-m33`) + LAN IP (`public_ip`/`geo`/`weather` are `null`).

## Layout

```
eth_http/
  src/app_main.c      entry: netmgr init -> wait for DHCP -> http_server_start
  src/http_server.c   lwIP-socket HTTP server (e_server API)
  src/http_server.h
  src/web_assets.h    generated by:  python ../../../../e_server/build_web.py --out src/web_assets.h
```

`web_assets.h` is regenerated from the e_server sources; do **not** edit it
by hand.

## Build

```
sh build.sh          # or: scons --board=haas100
```

## Flash & run

Board in download mode, from this directory:

```
./flash.sh
```

Then power the board normally (Ethernet cable connected to a bridge on the
host), open a serial monitor at **1500000** baud, and wait for:

```
eth_http: LAN IP 192.168.x.x
eth_http: listening on :80
```

Open `http://<that IP>/` in a browser.

## DHCP / static IP

The board uses the **stock netmgr flow** (`event_service_init` +
`netmgr_service_init`). The CH395 chip runs its own DHCP and netmgr
publishes `EVENT_NETMGR_DHCP_SUCCESS` when a lease is obtained.

By default (`src/app_main.c`) the app then overrides to a **static IP**
(`192.168.5.50`, same subnet as the host) to avoid an IP conflict when the
host bridge hands out the same address to the board. This is controlled by
the `netmgr_set_ifconfig()` block in `src/app_main.c`:

```c
netmgr_hdl_t eth_hdl = netmgr_get_dev("/dev/eth0");
netmgr_ifconfig_info_t cfg;
memset(&cfg, 0, sizeof(cfg));

/* true  = DHCP (ignore the static fields below)
 * false = static IP (use ip_addr/mask/gw/dns_server) */
cfg.dhcp_en = false;

strcpy(cfg.ip_addr,     "192.168.5.50");
strcpy(cfg.mask,        "255.255.255.0");
strcpy(cfg.gw,          "192.168.5.1");
strcpy(cfg.dns_server,  "192.168.5.1");
netmgr_set_ifconfig(eth_hdl, &cfg);
```

### Switch DHCP on

Set `cfg.dhcp_en = true;` (the four static fields are then ignored) and
rebuild. `netmgr_eth_set_ifconfig()` maps this to `NETMGR_ETH_IP_MODE_AUTO`.
The board takes whatever address the LAN's DHCP server hands out; the app
prints it as `eth_http: LAN IP <ip>`.

### Use a static IP (DHCP off)

Leave `cfg.dhcp_en = false;` and edit the four `strcpy` lines:

| Field         | Meaning                       | Typical value        |
|---------------|-------------------------------|----------------------|
| `cfg.ip_addr` | board's own IP                | e.g. `192.168.5.50`  |
| `cfg.mask`    | netmask                       | e.g. `255.255.255.0` |
| `cfg.gw`      | gateway                       | e.g. `192.168.5.1`   |
| `cfg.dns_server` | DNS resolver              | e.g. `192.168.5.1`   |

The IP must be unique and on the same subnet as the host/router, otherwise
the web page won't load. After flashing, open
`http://<cfg.ip_addr>/` in a browser.

> Note: `netmgr_eth_get_ip_stat()` (used by `/api/info`) reads the
> **netif** IP, so both modes report the live address.

## Notes

- The app does **not** call `tcpip_init()` or create the netif — that happens
  at boot in `startup.c` via `eth_lwip_tcpip_init()` (stock HaaS100 flow).
- **`TCP_NODELAY` is required** on HTTP sockets: on the CH395 MAC-raw link,
  lwIP's Nagle algorithm defers sending the response body until the previous
  header segment is ACKed, and those ACKs are delayed, stalling large
  transfers (small responses worked; large pages hung). Setting
  `TCP_NODELAY` on each accepted connection fixes it.
- `public_ip`/`geo`/`weather` in `/api/info` are `null` on the board (no HTTP
  client), matching the e_server contract.
